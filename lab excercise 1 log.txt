package week2.day2.assignment1;

import java.util.Scanner;

public class BillingApplication {

    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter customer name: ");
        String customerName = scanner.nextLine();

        System.out.print("Enter product name: ");
        String productName = scanner.nextLine();

        System.out.print("Enter product price: ");
        double productPrice = scanner.nextDouble();

        System.out.print("Enter quantity: ");
        int quantity = scanner.nextInt();

        double totalAmount = productPrice * quantity;
        double discountAmount = calculateDiscount(totalAmount);
        double finalAmount = totalAmount - discountAmount;

        printBill(customerName, productName, totalAmount,
                  discountAmount, finalAmount);

        scanner.close();
    }

    // Calculates and returns the discount amount in rupees
    public static double calculateDiscount(double totalAmount) {
        double discountPercentage = 0.0;

        if (totalAmount >= 1000 && totalAmount < 5000) {
            discountPercentage = 5.0;
        } else if (totalAmount >= 5000) {
            discountPercentage = 10.0;
        }

        double discountAmount =
                totalAmount * discountPercentage / 100;

        return discountAmount;
    }

    // Prints the completed billing details
    public static void printBill(String customerName,
                                 String productName,
                                 double totalAmount,
                                 double discountAmount,
                                 double finalAmount) {
        double discountPercentage;

        if (totalAmount >= 1000 && totalAmount < 5000) {
            discountPercentage = 5.0;
        } else if (totalAmount >= 5000) {
            discountPercentage = 10.0;
        } else {
            discountPercentage = 0.0;
        }

        System.out.println("\n===== SmartStore Billing Details =====");
        System.out.println("Customer Name: " + customerName);
        System.out.println("Product Name: " + productName);
        System.out.printf("Total Amount: Rs. %.2f%n", totalAmount);
        System.out.printf("Discount Percentage: %.2f%%%n",
                          discountPercentage);
        System.out.printf("Discount Amount: Rs. %.2f%n", discountAmount);
        System.out.printf("Final Amount: Rs. %.2f%n", finalAmount);
    }
}

# Understanding JUnit Assertions

## 9. Assertion Format

**Code:**

```java
assertEquals(expected, actual, 0.001);
```

**What it does:**

Compares the expected result with the actual result returned by the method being tested.

**Why required:**

Allows JUnit to automatically determine whether a test passes or fails.

**Java concept:** JUnit assertions.

### Explanation of Parameters

| Parameter | Meaning |
|---|---|
| `expected` | The correct discount amount calculated by the test. |
| `actual` | The value returned by `BillingApplication.calculateDiscount()`. |
| `0.001` | The permitted difference between the two values. |

### Understanding the Delta (0.001)

The third parameter is called the **delta**.

It specifies how much difference is acceptable between the expected and actual values.

**Example:**

```java
assertEquals(50.0, actualDiscount, 0.001);
```

The test passes if the actual value is between:

```text
49.999 and 50.001
```

The test fails if the actual value falls outside this range.

**Why is delta used?**

Java's `double` data type can produce small floating-point precision differences.

For example, a calculation might produce:

```text
Expected: 50.000
Actual:   49.999999999
```

Using a delta prevents insignificant floating-point differences from causing a test to fail.

Logical Issues

	•  No input validation: Negative prices or quantities can produce incorrect totals and discounts.
	•  Zero or non-numeric input: The Scanner has no validation for invalid values or input failures.
	•  Mixed validation in display logic: printBill() independently repeats the discount-percentage calculation instead of receiving the percentage.

	•  Floating-point currency precision: double can introduce rounding errors. Monetary applications should prefer BigDecimal, although that may be considered more advanced Java.
	•  Discount percentage and amount can become inconsistent: Both calculateDiscount() and printBill() implement the discount rules separately.

Security and Reliability Issues

	•  Untrusted console input: Without validation, unexpected input can cause exceptions.

	•  Scanner resource handling: scanner.close() is safe in this program but could prevent reuse if placed in a reusable application component.
	•  No exception handling: The application may terminate abruptly after invalid input.
	•  No decimal or overflow checks: Extremely large values may overflow or lose precision.
	•  Console output only: There is no audit trail, transaction storage, or logging.

package week2.day2.assignment1;

import java.util.Scanner;

public class SalaryCalculator {

    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        // Accept employee details
        System.out.print("Enter employee ID: ");
        int employeeId = scanner.nextInt();
        scanner.nextLine();

        System.out.print("Enter employee name: ");
        String employeeName = scanner.nextLine();

        System.out.print("Enter basic salary: Rs. ");
        double basicSalary = scanner.nextDouble();

        // Calculate salary components
        double houseRentAllowance = basicSalary * 20 / 100;
        double dearnessAllowance = basicSalary * 10 / 100;
        double grossSalary =
                basicSalary + houseRentAllowance + dearnessAllowance;

        // Professional tax is deducted only when gross salary is above Rs. 20,000
        double professionalTax = 0.0;

        if (grossSalary > 20000) {
            professionalTax = 200.0;
        }

        double netSalary = grossSalary - professionalTax;

        // Display employee salary details
        System.out.println("\n===== Employee Salary Details =====");
        System.out.println("Employee ID: " + employeeId);
        System.out.println("Employee Name: " + employeeName);
        System.out.printf("Basic Salary: Rs. %.2f%n", basicSalary);
        System.out.printf("HRA: Rs. %.2f%n", houseRentAllowance);
        System.out.printf("DA: Rs. %.2f%n", dearnessAllowance);
        System.out.printf("Gross Salary: Rs. %.2f%n", grossSalary);
        System.out.printf("Professional Tax: Rs. %.2f%n", professionalTax);
        System.out.printf("Net Salary: Rs. %.2f%n", netSalary);

        scanner.close();
    }
}

# Follow-up Question

**What is the difference between `scanner.nextInt()` and `scanner.nextLine()`, and why is `nextLine()` called after `nextInt()`?**

### Answer

`scanner.nextInt()` reads an integer value but does not consume the newline character generated when the user presses Enter.

`scanner.nextLine()` reads the complete remaining line, including spaces, and consumes the newline character.

**Example:**

```java
int employeeId = scanner.nextInt();
scanner.nextLine();

String employeeName = scanner.nextLine();
```

The first `nextLine()` consumes the leftover newline after the employee ID.

The second `nextLine()` reads the employee's actual name.

**Without the extra `nextLine()`:**

The program may skip the employee name input because the leftover newline is consumed immediately.

**Remember:** When mixing `nextInt()` or `nextDouble()` with `nextLine()`, be aware of the leftover newline character.
